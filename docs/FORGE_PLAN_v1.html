The Forge

A guided pipeline that walks anyone — including pure vibe coders — from “I have an idea” to “I shipped a product,” with the expert judgment encoded in the skills. Built on five deep-research passes and hardened by an adversarial gap-check.

Why this can win

The 2025–26 evidence says the niche is open. Spec Kit buried a developer in 2,577 lines of markdown for one feature (3.5 hours of review). Kiro turned a minor bug into 16 acceptance criteria. BMAD produced a 500-page brief and claims non-dev accessibility its own users refute. Every surviving framework was forced to retreat to “right-sized process.” Nobody has shipped calibrated, brevity-capped, verified guidance for non-experts — that's the Forge's slot.

Locked decisions

✓
State lives in the target project — a .forge/ folder travels with each project.
✓
Backlog is local-first — backlog.md now; GitHub-issues sync at launch.
✓
Stage skills + dispatcher — /moradin:forge reads state and routes.
✓
Forge front door, memory behind — no teardown.
✓
Measure is its own stage — success criteria before any tool research or code.

Nine design laws

Distilled from the research; they override everything else in the plan. Each traces to documented failures of existing frameworks.

Right-size per task, not per projectKiro, BMAD, and Anthropic all had to patch in a quick path. The dispatcher routes every entry.
Hard size budgets on every artifactSpec Kit's 2,577-line feature. Every file capped; prose only where a human decision is encoded.
Checks and hooks, not proseAgents demonstrably ignore markdown rules. Non-negotiables become hooks; every slice has a runnable check.
No summary chainsTask Master lost 80% of a PRD decomposing from summaries. Slices cite and re-read their sources.
Specs are scaffolding, not truthThe code is the product; Close reconciles files against reality, both directions.
No persona agentsBMAD's role-play: 10–15× slower. Perspectives are prompts inside a stage, never handoffs.
Context economyStage files load on demand; fresh session at the Decide→Build boundary, with literal plain-language instructions.
Agent never touches prod dataReplit wiped a live DB during a code freeze. Dev/prod separation from slice one; verify-after-write.
Facts that rot live in memory, not skillsTool defaults sit in a dated, monthly-reverified reference — Highlight.io died during our own research window.

Calibrate

inside /forge, first run

Plain-language interview → Light / Medium / Full profile. “I don't know what that is” counts as an answer. Profile sizes guidance depth — it never removes safety items. Re-run any time.

writes .forge/profile.md
1

Define

/moradin:define

An interview, not a form — the Forge drafts, the operator corrects. Certainty-first: ~43% of failed products die from “no market need,” so who + problem come before any feature talk.

  • Light, 6 steps (10–15 min): who + problem → job story → riskiest assumption → walking skeleton (5–7 steps, each a story) → appetite + binary cut → premortem-lite.
  • Full adds: user types, directional outcome before solutioning, evidence check (“how do you know this problem exists?”), acceptance criteria, non-goals, full premortem, milestones with appetites.
  • Never: RICE, opportunity trees, Should/Could tiers, effort estimates.
writes .forge/plan.md (capped 2/5 pg) · seeds backlog.md
2

Measure

new stage/moradin:measure

Before tools or code: what does working look like, in numbers? Output is a one-page Success Contract:

  • One metric that matters — stage-labeled, with a target and a kill/pivot threshold; the threshold turns the number into a decision.
  • Max 3 supporting signals · an anti-vanity list (what we will NOT count) · two horizons (launch-week activation, month-3 retention/revenue).
  • The traffic question: “where do the first 20 users come from, concretely?” — “nowhere yet” triggers the validation gate.
  • Validation gate: no evidence or no traffic ⇒ milestone 0 is a landing-page test with a pre-build metric; pass ⇒ build, fail ⇒ pivot or clean stop.
  • Instrumentation named now (from the dated tool reference; Sean Ellis question as the zero-setup fallback) · review date +30d, read by the dispatcher.
writes .forge/measure.md (1 page)
3

Research

/moradin:research

Generates its own research questions from plan + contract, confirms which matter, then runs the expert method — timeboxed by door type (data model and payments get real research; a swappable UI library gets minutes).

  • 8-check verification per option, no claim from memory: live existence check (19.7% of LLM package recommendations were hallucinated) · pricing page fetched today · 24-month pricing history · maintenance signals (never stars) · adoption trend · issue responsiveness · lock-in probe with exit path · UNVERIFIED labeling.
  • Named risk category: free tier + usage billing + no spend cap (Netlify $104k, Cara $96k, PlanetScale rug-pull).
  • Boring-by-default — mainstream stacks are also what AI builds most reliably on; innovation tokens tracked.
writes .forge/research/<topic>.md · HTML options report for review
4

Decide

/moradin:decide

Constraints elicited before options are shown. Then per decision: exactly 3 options + 1 recommended default, each with cost now and at 10×, spend-cap status, exit cost in days, and a “pick this if…” sentence. Non-dev triage on every choice: accept the default / defer / explain in plain language.

Each choice appends a Nygard-lite record: context, decision, why (tied to stated constraints), rejected options with why-nots, door type, innovation token, verified-on date, and event-based “revisit when” triggers. accepted is never relitigated except by explicit supersession or amendment.

writes .forge/decisions.md (append-only, ~15 lines/record)
5

Build

/moradin:build · rewritten

Plan + decisions become vertical slices, each citing its plan sections + decision IDs and defining its executable check up front. Per slice: checkpoint → align → build (dev data only) → run the check → tick + checkpoint.

  • [you] operator setup tasks — the human-only work every framework ignores: creating accounts, pasting keys, setting spend caps in dashboards, pointing DNS. Written as plain-language walkthroughs; the agent verifies each before the dependent slice proceeds.
  • Scope creep → backlog, never silent expansion · API pre-flight before building around any external service · first deploy slice wires monitoring (Sentry + UptimeRobot, $0) and the contract's analytics events · hooks installed (secrets scan, prod-connection block, slice-check gate).
writes .forge/checklist.md — the resume point
6

Close

/moradin:close · absorbs ship

Every item traces to a documented 2025 incident. Core/Extended keys to release significance (first public launch or PII ⇒ Extended) — never to operator profile, because the incidents all happened to Light-profile builders.

Core — every ship (30–60 min)

  • Secrets scan over full git history — hits rotated, never deleted
  • Logged-out probe of every endpoint/table/bucket — expect denial
  • DB rules via the platform's own linter
  • Backup on + one real restore performed
  • Spend caps + billing alerts on every metered API
  • Monitoring receives a deliberate test error
  • Production smoke test of the golden path
  • Working contact/feedback route (also the data-deletion path)
  • Collects personal data? → privacy policy + terms + deletion route
  • Closed-loop audit: everything done or deferred with a reason
  • Converge: reconcile .forge/ ↔ code, both directions
  • Four-question retro → lessons to Moradin memory

Extended — first public launch

  • Rate limiting on auth + expensive endpoints
  • Dependency audit + unused-dep removal
  • TODO/mock/dead-code sweep
  • Legacy-data purge (old buckets, dev DBs, seeded PII)
  • Prompt-injection trifecta review — unconditional if any LLM feature
  • Adversarial code review: fresh-context subagent over the diff
  • Cost audit of every service signed up during build
  • README verified from a clean clone
  • Platform-trust check — verify auth yourself
also writes session log + projects/<name>/state.md (keeps retrospect fed)
7

Review

new stage/moradin:review

The loop-closer — the stage that consumes the Success Contract. Runs when the review date passes or the operator returns. Pulls actuals from instrumentation, compares against targets and the kill threshold, and routes explicitly:

  • Continue — trending to target: pick the next milestone from backlog, re-enter Build.
  • Pivot — threshold hit, problem still real: amendment back through Define.
  • Stop — thesis dead: close cleanly, capture the lesson. A clean kill is a success of the process.

Also the v1→v2 re-entry point, and it refreshes the contract for the new stage — yesterday's north star is tomorrow's vanity metric.

Build order

Each phase ends with a dogfood pass on a real project before the next begins.

Foundation

Templates (incl. journal) + dispatcher (routing, quick path, amendment) + define + measure + the tool-defaults reference. Usable immediately.

Research engine

research + decide: 8-check verification, HTML options report, decision records. The most differentiated piece.

Build, close, review

Rewrite build (slices, [you] tasks, hooks), create close + review, retire ship.

Launch polish

Identity docs + README, GitHub-issues sync, shareable packaging with FEEDBACK.md, calibration reading preferences.
