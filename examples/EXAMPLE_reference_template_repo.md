# Example Reference (illustrative only)

## What it is

This file is an EXAMPLE showing how to structure a reference. Replace this content with a real captured source when you use `/moradin:capture`.

## Notable concepts (full inventory, NOT pre-filtered)

### A. The capture-everything discipline

When capturing an external source, list ALL notable concepts — not just what fits the current project. A concept that doesn't fit GodTech today may be exactly what trading needs next month.
Applicability: universal — this is THE rule for reference capture.

### B. Tag philosophical contrasts

If a source argues for an approach that contradicts your current design, capture it anyway. Tag with potential applicability and note the contrast.
Applicability: universal.

### C. Skipped content gets a section too

Don't silently drop the boring tactical detail — list what you deliberately skipped so future you knows it was a deliberate choice, not an oversight.
Applicability: universal.

## What I deliberately skipped

- The actual content of an external source (this is an example file, not a real capture)
- Setup steps for any specific tool (those go in QUICKSTART, not in references)
